# 外部专业能力 Owner 手验路径

## 材料
- `authorized-project-brief.md`：授权可见
- `unauthorized-secret.md`：明确不授权（不得出现在成果中）

## 任务
请根据已授权材料，形成 500–800 字结构化项目风险摘要。

## 步骤
1. 启动参考研究能力（另开终端）：
   ```
   cd digitalme-v2
   npm run start:reference-research-agent
   ```
   看到「已启动」与服务地址后，再运行：
   ```
   npm run verify:reference-research-agent
   ```
   确认 `ready_for_connection=true`。**不要**进入设置页管理外部能力，**不要**设置环境变量。
2. 正常启动 Digital Me 产品壳（`npm run dev` 或既有启动方式）。一级导航应为：数字之我 | 对话 | 做事 | 协作 | 设置。
3. 打开「协作」→「协作对象」→「外部专业能力」：
   - 点击「连接」；
   - 在「连接外部专业能力（高级）」中填写服务地址（建议复制启动输出的 `http://127.0.0.1:…`）；
   - 点击「检查连接」，再「保存并连接」。
4. 打开「做事」→「使用已连接的外部专业能力」：
   - 确认能力显示为可用；
   - 勾选授权材料，不勾选干扰材料；
   - 查看授权说明后开始使用。
5. 观察状态：准备中 → 正在交给专业能力 → 正在处理 → 正在检查成果 → 已返回成果。
6. 取消一次，确认迟到成果不进入成果区。
7. 正常完成一次；采用 / 不采用各试一次。
8. 关闭并重启应用（无需再填环境变量），确认连接配置仍在，进行中任务可恢复且不重复。
9. 回到「协作」点击「停用」后，做事页应提示尚未连接，并提供「前往协作」。

## 检查点
- 数字之我与协作并列，当前主体只在「数字之我」管理
- 外部专业能力连接只在「协作」，不在「设置」
- 能看懂这是外部专业能力，不会误解为另一个数字之我
- 清楚发送了什么；未授权材料隔离
- 失败时不出现 IPC / shell: 内部异常原文
- 无需编辑 `.env` 或 PowerShell 环境变量

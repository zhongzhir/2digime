## 2. 用户表达如何进推荐

- 发现页「调整推荐」→ 模型理解 → `recommendation-adjustment.json`
- **仅本次**：只作用于默认推荐，**不是当前进程**。换主题搜索不自动套用；若文件仍在，页面必须显示，并写明「这次搜索按你刚说的主题」。
- **持续保留**：同时写入已有 `content-preferences` 的 `steer`，出现在内容偏好页，可撤销
- 默认流的搜索方向与排序会带上本次调整；明确 seek 以当前主题为准
- 打开 / 稍后看 / 一次搜索仍不是喜欢，也不写数字之我
- 「最近看剧有点多了…」必须带「本次」，不得写成「用户不喜欢看剧」

## 3. 可见控制

为你发现：调整推荐 · 本次调整摘要 · 范围说明 · 修改调整 · 撤销 · 持续保留  
信息不够时只显示一个关键问题。瀑布流未改。

## 4. 默认流为何仍容易全是文章

不是用户把类型偏好设成了只要文章，也不是固定类型配额。

| 原因 | 是否成立 | 说明 |
|---|---|---|
| 用户偏好 | 否（默认无类型偏好） | 打开/收藏仍不是喜欢 |
| 来源获取 | 部分 | RSS 以文章为主；Bangumi/Steam/维基导游本机可取，但不能当国内唯一供给 |
| 候选相关性 | 部分 | 作品常被存成 `article`，新闻又有发布日期，旧逻辑按日期把无日期作品压到后面 |
| 排序失败 | 可能 | 模型若只看见文章窗，就只能排文章；失败回退也只展示该窗 |

本批：目录媒体与作品交错入库；候选窗在已取到作品/媒介时给它们一个被看见的位置。**不设类型配额。** 国内未验证来源不得承担唯一供给。首页仍可能文章偏多——那是供给结构，不是质量通过。

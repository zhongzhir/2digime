# 02 — FAILURE LESSONS

**状态：** `current_authority`  
**日期：** 2026-09-01  
**性质：** 旧版本失败史、根因、禁止事项、Yellow / Red 报警。出现报警必须重读本文及 00、01。

来源吸收：`digitalme_rules.md`、`digitalme_log.md`、`digitalme_context.md`、`docs/reviews/DIGITALME-CORE-STAGE-REVIEW-01.md`、DIGITAL-SELF 依赖图与 ADR、01A baseline §3、专项 benchmark。本文是失败教训的唯一现行文件；旧处保留历史叙述，不再当现行清单。

---

## 报警规则

### YELLOW

同一问题连续 **2** 轮修改仍未真实改善，**或者**讨论重心变成 flag / state / listener / 兼容分支，而不是用户目标。

→ **停止继续补丁**，重读 00 / 01 / 02。检查是否又用确定性逻辑覆盖 AI，或又引入第二事实源。

### RED

同一问题第 **3** 轮仍在原层修复，**或者**必须增加第二事实源 / 新状态机 / 大量例外才能成立。

→ **强制停止该实现**，回到对象模型与用户主链重新审计。不准再请 Owner 复验同一按钮。

「真实改善」指正式入口上的用户感受，不是专项测试变绿。

---

## L1. AI 判断被 deterministic logic / enum / keyword 覆盖

- **现象：** 对话靠句式正则分流；做事靠目标关键词判 intent；协作接受/拒绝靠风险词；搜索曾靠 keyword 扩面。换一种说法就错。
- **根因：** 把「对 fixture 可测」当成「能理解语言」。
- **当时错误处理：** 继续加高精度句式（GROWTH-CONTEXT 01A–01E）、风险词表、intent 枚举；局部 Owner 通过后当作路线正确。
- **最终经验：** 开放语义必须由 AI 承担；代码只守不变量和安全边界。薄约束仅限用户显式「不要联网 / 取消」和授权校验。
- **今后禁止：** 关键词总路由、封闭 `TASK_INTENT_KINDS`、用正则当理解层、`if DeepSeek` 品牌路由。
- **报警：** 新增 regex/enum 才能让某句用户话成立 → 至少 YELLOW；把它写成永久路由键 → RED。

## L2. Case patch

- **现象：** 「你叫什么名字」抽出「什么名字吗」；资料查询靠场景句式；GitHub URL 反斜杠再补一条解析。
- **根因：** 把用户抱怨的句子当成需求规格。
- **当时错误处理：** 加抽取器、加测试、把泄漏行为 characterization 成绿。
- **最终经验：** 同一问题必须升到主体或 Intelligence 层。Owner 已要求停止句式修补（DIGITAL-SELF-CORE 立项）。
- **今后禁止：** 针对已出现句式、网站、文件名增加永久分支。
- **报警：** 第二轮仍在加特例 → YELLOW；第三轮仍在原抽取器上修 → RED。

## L3. 状态 / 字段 / Store 膨胀

- **现象：** `Task.meta` 塞 conversation/plan/revisionLoop/runtimePath/capabilityLoop；协作 12 态；renderer 近万行；大量「建好未开」UI。
- **根因：** 每修一个体验就加永久字段或隐藏入口，而不是收口投影。
- **当时错误处理：** 注释写「不是第二状态机」，字段仍在 schema 里。
- **最终经验：** 新增永久对象必须通过 01 的证明义务。没有用户新决策就没有新阶段。
- **今后禁止：** thin_v1/legacy 双轨、11 相 capabilityLoop、为单个功能新增永久 Store。
- **报警：** 讨论开始围着 flag/state/listener 转 → YELLOW；靠新状态机才能成立 → RED。

## L4. 第二事实源

- **现象：** 同一用户在对话/规划/执行/协作被理解成不同的人。页面「已经了解」，对话「一无所知」。`detected.name` 绕过确认。至少六套准权威。
- **根因：** 各模块自行定义用户；兼容层变成第二产品。
- **当时错误处理：** 强制某两处读同一投影，不拆权威。阶段复盘仍写「0 第二真值源」。
- **最终经验：** 全系统一个 Current Subject。读取失败不得解释为空白人格。
- **今后禁止：** 第三套 Profile/memory；双写双权威；material-index 检测字段当事实。
- **报警：** 为了「先接上」再写一条用户镜像 → RED。

## L5. UI 与 Runtime 多权威

- **现象：** 主体闲聊会话 vs `Task.meta.conversation`；renderer 正则 scrub 与主进程过滤并行；UI 理解 `thin_v1`、Job 五态。
- **根因：** 页面持有业务状态；主进程与渲染层各有一份「现在发生了什么」。
- **当时错误处理：** 再加一层投影模块，上帝 `app.js` 仍在。
- **最终经验：** UI 只投影。删除 UI 后主体与 Goal 逻辑仍须成立。
- **今后禁止：** 渲染层作为事实源；用 scrub 代替投影 API。
- **报警：** 修 UI 状态才能让结果「看起来对」而领域对象未绑 Goal → YELLOW；必须保留双存储 → RED。

## L6. Task / Job / Artifact 被用户界面直接消费

- **现象：** 资料查询建成 Task/成果卡；后一句覆盖当前任务；「采用」又开 Coding Job；迟到 Job 画到另一任务。
- **根因：** 内部执行对象被当成用户目标；异步结果不核对身份。
- **当时错误处理：** 逐项语义修复和 epoch 核对——正确但是补丁。
- **最终经验：** 用户面对 Goal、人话进展、结果、需要自己决定的事。Execution 绑定 `goalId`。
- **今后禁止：** 把 Job 相位、seed_internal、capabilityLoop 展示给用户。
- **报警：** 为对上某个 DOM 而给 Task 加展示专用字段 → YELLOW。

## L7. 测试冻结错误设计

- **现象：** characterization 断言泄漏姓名等于「什么名字吗」；坐标点击/错误 probe 被写成 Owner 通过；场景句式测试保护补丁路径。
- **根因：** 测试锁当前行为，不是产品不变量。
- **当时错误处理：** 用更多专项证明补丁，而不是淘汰坏合同。
- **最终经验：** characterization 只允许标 `legacy_must_not_port`。绿测不是产品完成。
- **今后禁止：** 把已知错误行为写成生产断言。
- **报警：** 新测试在固化「旧路径必须如此」且与 00 冲突 → RED。

## L8. mock / 专项绿但真人体验失败

- **现象：** 成果打开自动化全绿，Owner 正式页无反馈；MCP hook 绿 ≠ 官方 MCP；协作 runtime 真闭环但履行 UI 全关；PAN-01R 70/70 仍产品感知失败。
- **根因：** 测的不是用户走的路。
- **当时错误处理：** 更像真人的 harness + 继续催 Owner 复验。
- **最终经验：** 分层必须写进报告。正式入口未过不得标完成。
- **今后禁止：** 用 hook 成功宣称外部能力已可用。
- **报警：** 专项绿、正式入口未跑就请 Owner → YELLOW；第二轮仍如此 → RED。

## L9. 历史兼容绑架新设计

- **现象：** 多套打开成果入口；GrowthEvent 与新核并行；legacy 与 thin_v1 双轨。
- **根因：** 害怕破坏旧测试和旧包。
- **当时错误处理：** 保留旧路径并继续在上面施工。
- **最终经验：** 兼容层必须可删除。迁移期禁止双写。不能安全迁移的旧数据降级，不得污染新核。
- **今后禁止：** 用「旧测试还在」否决 00 已冻结的原则。
- **报警：** 新设计开始迁就旧字段名 → YELLOW；两套权威同时可写 → RED。

## L10. 弱自研能力替代成熟 Agent

- **现象：** Bing HTML 当主搜索，P95 引用门槛达不到；本地启发式当协作判断；无专业能力时用写文章冒充执行。
- **根因：** 「我们也能做一点」替代「去调用会做的人」。
- **当时错误处理：** 在弱提供方上继续打质量补丁。
- **最终经验：** 没有可靠能力就诚实停住或交接，不许假完成。
- **今后禁止：** 重复开发成熟 AI 产品核心；`general → document` 冒充已完成。
- **报警：** 为一种新任务先写本地弱实现而不是找成熟 Agent → YELLOW。

## L11. Owner 被拖进工程调试

- **现象：** 成果打开 FIX-01A/B/C/D 连环；probe 路径错误仍安排复验；最终 `owner_retest_forbidden`。
- **根因：** 把 Owner 当集成测试器，且根因多次判断错误。
- **当时错误处理：** 每一轮都「再请 Owner 看一下」。
- **最终经验：** 开发者鼠标/正式入口未过，不得送 Owner。产品成败不得依赖 Owner 会调试。
- **今后禁止：** 用 Owner 截图对比 DOM 当开发步骤。
- **报警：** 同一按钮第二次请 Owner → YELLOW；第三次 → RED。

## L12. 同一问题反复修补

- **现象：** 姓名/关于我、成果打开、任务串台、能力缺口，各自经历多轮同层修复；数字之我仍未成立。
- **根因：** 把架构缺口当成缺陷列表。每轮局部绿，主链不收敛。
- **当时错误处理：** 开下一个 FIX 编号，而不是停下来重读原则。
- **最终经验：** 2 轮黄灯、3 轮红灯。红灯后禁止原层继续。这正是 01C 先做上下文权威对齐、再做 02-DIGITAL-SELF 的原因。
- **今后禁止：** 在未重读 00/01/02 的情况下对同一用户主链开第 3 个补丁任务。
- **报警：** 任务名出现 FIX-01C/01D 或「再修一次同一入口」→ 至少 YELLOW。

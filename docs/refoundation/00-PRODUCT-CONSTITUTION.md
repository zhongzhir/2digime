## 1. 2digime 是什么

2digime 是由本人拥有和控制、以本人为源头持续形成的个人数字主体系统。它能够形成一个有证据、可解释、可纠正、可撤销、持续演化的数字之我；在明确授权下代表本人理解、判断、表达、行动；调用外部智能能力完成真实任务；作为属于真人的智能网络节点存在于数字主体网络中。

**2digime 是属于人的数字之我，也是人的超级助手。**

超级助手拥有足以处理多数一般事务的通用能力；自身能力不足时，应自行发现、学习、获取、安装、连接、调用模型、Agent、Skill、Tool、软件、服务或其他数字主体，组织这些能力持续完成主人的目标。主人原则上只需要表达诉求。技术实现、工具选择、安装配置、能力调度、普通失败恢复属于 2digime 自己的职责。只有涉及：资金、隐私、授权、重要资源、对外承诺、不可逆动作、高风险行为，或者只能由主人作出的价值判断，才请求主人决定。2digime 不是把工具交给主人自己操作，而是代表主人获得、组织和使用能力，把目标变成结果。

> 2digime 是你的数字主体：属于你、能为你做事、连接世界，并在使用中成长为更准确的你。

### 1.1 超级助手分层目标

| 层 | 名称 | 含义 | 当前 |
|---|---|---|---|
| **L1** | 通用超级助手 | Owner 表达目标；模型直接完成一般事务，或自主调用已连接成熟能力；可靠交付最终结果 | **本阶段实施** |
| **L2** | 自我扩展助手 | 能力不足时自行发现/获取/安装/连接新能力；acquisition 不锁定单一品类 | **建立最小基础** |
| **L3** | 资源组织助手 | 组织本地软件、文件、账号、服务等多资源完成目标 | 后续 |
| **L4** | 网络化超级助手 | 经 Digital Subject Network 连接其他主体与服务 | 后续 |
| **L5** | 主动型数字管家 | 在授权与边界内主动跟进、提醒、维护长期目标 | 后续 |

当前只实施 L1，并建立 L2 的最小基础（通用 acquisition 合同可复用；OpenCode 仍是第一个真实实例）。不做视频/图片/数字人专项、不做能力商店、不做第二套 workflow。

## 2. 不是什么

不是聊天机器人、提示词套壳、传统 workflow/BPM、按任务类型拼盘的工具箱、静态简历/人设卡、自研 IDE/搜索引擎/深度研究产品、社交匹配或支付网络（长期可成为伸展，不是本体）、也不是仅为当前 Owner 调教的 Demo。

**不是通用大模型厂商的竞争对手。** 不自研搜索去比搜索，不自研 Coding Agent 去比 Codex / Cursor / Claude Code，不自研 Computer Use、Office 智能、音视频图片基础生成。能接不造。当成熟外部能力已能满足目标用户主要任务约 95 分位，停止自研该基础能力。

来源：`digitalme_context.md` §3、§5.4 通用产品身份、`digitalme_rules.md` §3、01A §1.2。归宿：本文。

## 3. 为什么存在

AI 越强，人越容易被平台和模型吸收。2digime 存在是为了让人在数字世界里仍有一个属于自己的主体：自我定义、自我发展、对外行动、可带走。没有数字之我，做事只是通用助手；没有做事能力，数字之我只是档案柜；没有数字主体网络，主体无法进入他人的世界、无法自主选择信息与连接。

来源：`digitalme_context.md` §1–§2.0、主权叙述、01A §1.3。归宿：本文。

## 4. Digital Self — AI Capability — Digital Subject Network

三者是同一主体的伸展，不是三个产品。旧称「代表我 — 做事 — 协作」容易把第三核心误读成「人与人通过 2digime 协作」。正式核心结构为：

```text
Digital Self              数字之我
AI Capability             AI 能力 / 做事
Digital Subject Network   数字主体网络
```

对外可用更自然的中文：**属于我 · 能做事 · 连接世界**。

- **Digital Self / 数字之我**回答：我是谁、我想要什么、什么属于我。包括身份、记忆、目标、判断、偏好、边界、关系、长期成长；在使用中持续逼近真人并继续演化。
- **AI Capability / AI 能力**回答：我能够做什么。原则：AI First；Build-vs-Integrate；成熟模型 / Agent / Skill / Tool 优先；用户无需自己搭 AI 工具链；2digime 从聊天开始帮助用户自动获得能力。Zero-start Coding 是第一条真实验证。
- **Digital Subject Network / 数字主体网络**回答：我如何存在于网络、获取信息、选择内容、连接对象、形成关系并行动。**协作只是该网络的一种应用，不再作为第三核心的总称。**

**对话是统一入口，做事是行为/结果。** 用户只对 2digime 说话。交流、判断、编排、验收都在同一入口完成。当目标需要已连接外部能力实际执行时，由 2digime 调用该能力并验收后再交付；不得做成「先选聊天还是做事」、按任务类型分产品，或让用户挑选 Agent / workflow。做事不是第二扇门，而是同一对话里发生的行为与外部结果。

当前建设顺序只在 03。本文只冻结关系：先有可纠正的「我」，做事才不是替陌生人工作；数字主体网络在数字之我与做事能力对真人成立的同时作为长期核心存在，但产品面扩建与实现顺序仍只由 03 决定。

来源：`digitalme_context.md` §2.0 双线、决策 #110、01A §1.4；2026-09-08 Owner 接受 DIGITAL SUBJECT NETWORK。归宿：本文（关系）；排期 → 03。

### 4.1 每一个 2digime 都是属于真人的智能网络节点

节点可以：publish、discover、subscribe、communicate、filter、select、reject、connect、establish relationship、exchange information、negotiate、collaborate、transact、调用 Agent / 服务。

其中最关键的创新不是通信协议本身，而是：**把「选择算法」从中心平台迁移到用户自己的数字主体。**

### 4.2 信息分发范式

传统互联网 / 移动互联网：

```text
内容 → 中心平台 → 平台画像用户 → 平台算法决定分发 → 用户被动接收
```

2digime Network：

```text
全网候选内容 / 主体 / 服务
  → Relay / Index / Search 等提供候选
  → 每个 2digime 自己理解候选
  → Digital Self + 当前目标 + 长期意图 + 边界 + 信任 + AI 推理
  → 每个 2digime 自主选择
  → 用户获得属于自己的信息流和连接
```

核心原则：**Digital Self 本身成为这个人的个人选择算法。** 禁止未来重新建设统一中心推荐算法，代替 2digime 做最终选择。关键词：DISTRIBUTED PERSONAL SELECTION。

### 4.3 自动化交互是网络主战场

真人之间通过 2digime 协作：**IMPORTANT**，但不是网络的主要定义。

更大规模的网络活动应发生于 2digime ↔ 2digime、2digime ↔ Agent、2digime ↔ Service、2digime ↔ Content，并大量自动完成：内容识别、信息筛选、主体发现、自动订阅、连接判断、关系建立、信息交换、简单协商、服务调用、协作、交易。

真人注意力只用于值得真人介入的部分。

### 4.4 Relay / 中间服务层

2digime Network **不意味着没有中间服务。** 未来仍需要活跃生态，例如：Relay、Index、Search、Storage、Hosting、Model、Compute、Identity service、Trust service、Payment / settlement、Content service、Capability marketplace。

这些服务可以商业化、相互竞争、专业化、大规模运营、收费。但其地位发生变化：

| | 传统中心平台 | 2digime Network 中间服务 |
|---|---|---|
| 同时控制 | 用户、数据、关系、算法、分发、商业规则 | 否 |
| 主要提供 | 网络主人权 | 技术能力、基础设施、候选供给、传输、索引、计算、存储、结算 |
| 不得天然获得 | — | 用户最终选择权；唯一身份控制权；数字主体所有权；唯一关系图谱控制权；最终内容分发权 |

一句话：**中间服务层不会消失，而会从「网络主人」退回为「网络服务商」。** 它们仍可能形成巨大的商业生态，但商业模式与网络权力结构都会改变。关键词：INTERMEDIARY SERVICE LAYER。

### 4.5 Web3 的借鉴边界

2digime 可以借鉴 Web3 的：主体自主、开放协议、可迁移身份、可迁移资产、服务商可替换、点对点价值关系、分布式网络、用户而非平台拥有网络身份与资产。

但：去中心化 ≠ 全部 P2P；去中心化 ≠ 没有服务器；去中心化 ≠ 全部上链；去中心化 ≠ 区块链优先。

判断标准只有：**谁拥有主体、谁控制数据、谁拥有选择权、谁能够迁移。**

### 4.6 三个核心形成演化循环

```text
Digital Self
      ↓
决定选择与目标
      ↓
AI Capability ───── Subject Network
      ↓                  ↓
完成任务             获取信息 / 关系 / 机会
      ↓                  ↓
成果 / 反馈 / 行为 / 选择 / 拒绝 / 关系
             ↓
        Digital Self
             ↓
          持续演化
```

Digital Self 不是一次构建完成。它随着工作、学习、娱乐、消费、阅读、社交、网络选择、协作、创造不断变化。

## 5. 数字之我如何成长

不是一次蒸馏出的人格复制，而是对用户的持续逼近：

观察（带来源、时间、范围、敏感级）→ 候选认识 → 确认/纠正/拒绝/失效 → 当前数字之我 → 按本次目的编译最小上下文 → 下一次理解与行动。

硬规则：

1. 全系统只有一个当前主体模型。
2. 材料是证据，不等于已确认事实。
3. 模型回复、系统文案、任务成果不得冒充用户事实。
4. 疑问、假设、引用他人、一次性任务要求不得写成长期身份。
5. 用户最新明确纠正覆盖旧认识，并在所有表面同时生效。
6. 删除材料或撤销授权后，失去全部证据的认识必须失效或降级。
7. 敏感信息默认仅本机；外发必须绑定任务、范围和接收方。
8. 读取失败不是「不了解用户」。
9. 必须能说明「这次用了什么、为什么、来源是什么」。
10. 校准不是限制：不因「像我」削弱通用 AI 能力；缺本人原料时用通用知识并区分来源。数字之我应让模型知道更多、理解更深、做得更好；禁止用 Digital Self 削弱模型、隐藏模型已理解的信息、固化用户、或用历史偏好锁死当前选择。

低风险知识可先成候选、高后果必须确认——写入门槛的产品取舍若仍有 Owner 未决，见 03，不在此自行裁定自动确认。

来源：DIGITAL-SELF-CORE-01 不变量与学习策略、ADR、`digitalme_rules.md` §8、`digitalme_context.md` 校准原则 #102、01A §1.5。归宿：本文。

## 6. 人、2digime、外部能力

| 角色 | 职责 |
|---|---|
| 人 | 源头与最终权威：表达目标、纠正「我是谁」、高风险/资金/隐私/授权/对外承诺/不可逆事项的决定、采用结果。原则上不当调试器，不自己选工具、装环境、排普通失败。 |
| 2digime | 数字之我 + 超级助手：维护数字之我、安全、授权、真实能力状态、真实执行事实；自行组织模型与外部能力把目标变成结果。不替模型做语义或技术判断。 |
| External Capabilities / Resources | 大模型、Agent、Tool、Skill、MCP、Computer Use、本地软件、网络服务、Other Subject。可替换。不得写主体事实，不得扩大授权，不得成为产品本身。 |

拓扑冻结：`用户 → 2digime → External Capabilities / Resources → 世界`。

Codex 是 Agent；Search 更像 Tool。调用接口可以统一，产品本体不要把所有东西都概念化成 Agent。

## 7. 主体性、所有权、迁移、授权、审计

- 对外可以数字之我为名义，主人永远是人。
- 主体数据、密钥、授权、成果默认在人本机可控的 Package 中；云与 Relay 不是事实源。
- Package 可拷贝、可导出、可在另一设备恢复；不绑定单一模型供应商。
- 授权最小必要、默认可撤销、不可暗中扩大。写文件、网络、账号、外发、付费分开展示。
- 关键行为可追溯。普通用户默认不看审计，需要时能打开。

长期 Digital Subject Network 的机械分层如下，彼此不得串层。协作是其中一层的一种应用，不是整个网络的总称。

| 层 | 回答 | 不是 |
|---|---|---|
| **Identity** | 这是谁的哪个数字主体 | 不是设备、不是 Agent Card 全文 |
| **Reachability** | 这次怎样安全送到对方 endpoint | 不是「值不值得合作」 |
| **Discovery** | 当前可发现谁、其公开协作面是什么 | 不是 Digital Self；不是广域市场 |
| **Collaboration** | 两边 2digime 如何谈、披露、做事、验收 | 不是传输状态机；不是用户协作中心 |
| **Transaction** | 以后钱/承诺是否真实发生 | 不是当前协作本体；无 receipt 就未付 |
| **Physical Interaction** | 以后与物理世界的交接 | 不是本阶段产品 |

**public-card** 是可发布的协作表面（身份引用、可达、公开技能/合作范围）。它不是 Digital Self authority，不得镜像 `self.json`。
**exchange** 是 append-only 交换事实（实际发了/收了什么）。它不是 workflow state，不表示「协作走到第几步」。

来源：`digitalme_context.md` 主权与本地优先、决策 #110 Relay 判断、`digitalme_rules.md` §5–§6、01A §1.7。归宿：本文。

## 8. 五个表面只是同一主体的投影

对话、做事、协作、数字之我、设置不是五个子系统，更不是五套用户定义。删除这些页面，主体与做事逻辑必须仍独立成立。

**对话（与 2digime）是统一入口。** 做事不是并列入口，而是该入口中的行为与结果。协作不是第三核心的总称，而是 Digital Subject Network 上的一种应用。

| 表面 | 底层 |
|---|---|
| 与 2digime | 人与 2digime 的统一语言通道：交流、判断、编排、验收 |
| 做事 | 同一通道里发生的外部执行与交付，不是第二产品 |
| 协作 | 同一 Goal 下、对端是另一 Subject 或 Agent 时的一种网络应用 |
| 数字之我 | Current Subject 的解释与控制 |
| 设置 | 连接、同意默认值、高级传输 |

来源：01A §1.8；Phase 2 核心闭环；推翻「对话\|做事\|我\|能力」作为五个产品（历史决策 #44 的页面结构 → 历史策略）。归宿：本文。

## 9. 战略定位（2026-09-08 Owner 确认）

**兔机米不是一个受 Digital Self 约束的大模型，而是大模型完整能力的主体化、持续化、增强层。**

正确关系：强大的通用大模型 + 属于用户的数字主体 + 真实外部能力 + 属于用户的网络节点 = 兔机米。

做事能力达到市场同类产品约 **95 分位** 是门槛，不是护城河。默认方式是接入、调用、编排当前最强的大模型、Agent、Skill、MCP / Tool、Computer Use、本地软件与外部服务，而不是重建这些能力。Zero-start Coding 已证明这条 AI Capability 路线可以在真人 Talk 中成立。

长期核心结构：

1. **Digital Self / 数字之我** — 属于用户，持续形成身份、上下文、经历、偏好、判断方式、目标、边界、资产、成果、经验、关系与成长；并成为这个人的个人选择算法。
2. **AI Capability / AI 能力** — 把最强 AI 能力变成属于这个用户的能力；用户无需自搭工具链；从聊天开始自动获得。
3. **Digital Subject Network / 数字主体网络** — 节点自主存在于网络：获取信息、选择内容、连接对象、形成关系并行动。协作只是其中一种应用。选择权在每个 2digime，不在中心平台。

系统只允许在大模型之上增加三类东西：**数字之我、安全、授权。** 除此之外，系统绝不替大模型做语义或技术判断。模型负责理解、推理、创造、判断、规划、工具选择与自我修正。系统负责数字主体、安全、授权、真实能力状态、真实执行事实。中间服务提供候选与基础设施，不得代替 Digital Self 做最终选择。

### 对外定位与推广

不要宣传「我们有自己的大模型 / Coding Agent / 搜索 / 造了几十个 Agents」。

正确卖点：**属于你的数字之我。** 它能使用不同 AI、连接最强 Agent / Tool、理解你、持续成长、代表你做事、作为你的网络节点自主选择信息与连接。

外部传播核心不是「又一个 AI Agent」，而是：AI 越来越强时，不是让人退出，而是让这些能力逐渐成为人的数字能力。兔机米代表人与 AI 共生，而不是 AI 替代人。对外可用：**属于我 · 能做事 · 连接世界**。

推广与商业合作强调：模型中立、工具中立、可迁移、开放、不被单一 AI 厂商绑定、用户主体性、能力持续增强、服务商可替换、选择权属于用户的数字主体。

# PRODUCT-CAPABILITY-AND-PARTNER-CLOSURE-01 — 产品能力、协作自动化与机构合作收口计划

**日期：** 2026-11-24

**状态：** `OWNER_DIRECTION_CONFIRMED / PLAN_REVISED / IMPLEMENTATION_IN_PROGRESS / SLICE_1A_DEVELOPER_VALIDATED`

**基线：** 本地 `main` 已快进到 `348226a`，包含 `INSTITUTIONAL-SUBJECT-COLLABORATION-01` Slice 1A–6；尚未 push、打包、发布或部署。

**目标：** 把已经存在的 Digital Self、Talk、Capability、Subject 协作、机构身份和授权地基，收束成普通用户能直接感知、能稳定使用、机构伙伴能演示和评估的产品能力。

## 1. 本次 Owner 验收形成的新事实

1. **发现仍未达到可用、好用。** 2026-11-24 打开默认信息流时，首屏出现 10 月 5 日、10 月 7 日内容；连续三四页后长时间中断；卡片高度、摘要与动作区不整齐。此前技术门不能覆盖当前真实数据新鲜度、连续供给和视觉质量。
2. **底层协作能力缺少产品投影。** 身份、授权、Relay/E2EE、A2A、接受/拒绝和结果事实已经存在，但用户没有入口理解、发起、管理或撤销协作与自动化。
3. **做事能力与领先产品差距明显。** 当前 Talk 不能稳定交付 Word/PPT/PDF，授权本地文件管理能力不完整，成熟 Coding Agent 接入没有在当前界面可靠可用，第三方系统实际操作能力也缺少可见证据。
4. **机构合作价值没有形成一条可演示主链。** 已有 Institution Distribution、OIDC、Owner identity、Subject binding、VC/VP 和 A2A 地基，但机构伙伴仍看不到“如何接入、能服务谁、能控制什么、不能读取什么、如何试点”。

以上不是四个平行产品。发现、做事、协作、自动化和机构服务继续是同一个 Digital Subject 的不同投影，共用 Digital Self、Goal、Execution、Artifact、Grant、Subject/Endpoint 和 Secret Store。

## 2. 路线裁定

### 推荐路线：能力先做实，再建立管理表面

1. 先修当前正式入口中最明显的 Discover 回退，避免继续用失真的首屏做试用入口；
2. 再按 Integrate-first 接入成熟 Office、授权文件、Coding Agent 和第三方系统能力；
3. 至少有一条真实协作和一条真实自动化成立后，再把管理入口逐步投影到“数字之我”右侧；
4. 最后用现有机构地基形成伙伴沙箱、机构侧控制台和接入资料包。

### 不采用的路线

- **新增“协作与自动化”一级入口或先建功能很多的协作中心：** 会增加用户入口负担并得到空壳 UI，重犯状态机、第二事实源和内部字段外露问题；
- **继续自研 Office、Coding、Computer Use 或第三方操作内核：** 无法接近 Codex、Claude Code 和成熟 Office 产品，违反 Integrate-first；
- **在 Discover 上继续加搜索供应商、站点特例和关键词规则：** 既有路线已进入 Red，且 Owner 已明确停止供应商扩张；
- **先做真实银行/电信生产接入：** 当前产品能力感知和伙伴演示链尚未成立，过早接生产只会放大交付风险。

## 3. 信息架构裁定：归入“数字之我”

不增加一级入口。顶部导航继续保持：


“数字之我”在桌面宽屏采用左右双栏；窄窗口保持同一页面并上下折叠，不增加新的一级导航：

| 左侧：系统如何认识我 | 右侧：我的身份、关系与行动边界 |
|---|---|
| 当前认知、来源证据、候选、冲突、确认、纠正、撤销 | 协作、自动化、个人身份认证、机构连接、授权与权限管理入口 |

右侧按需渐进显示，不一次堆满功能：

1. **身份与认证：** Owner identity、认证等级、已连接机构和恢复入口；
2. **授权与权限：** Grant、允许范围、有效期、人在环要求和撤销；
3. **协作关系：** 已验证个人/机构 Subject、邀请、发出/收到的请求、真实结果和停止；
4. **自动化：** 已启用规则、触发条件、授权范围、最近运行、暂停和撤销。

逻辑上两栏都属于 Digital Self：左侧回答“系统如何理解我”，右侧回答“我以什么身份、在什么授权下、与谁发生关系并代表自己行动”。右侧只是既有 Subject/Identity/Grant/Goal/Execution/Artifact 的控制投影，不建立第二个聊天入口、第二套 runtime 或新的权威 Store。

从右侧“发起协作”或“新建自动化”时，用户只表达目标，系统在原 Talk 中创建或打开对应 Goal；右侧负责查看、管理、暂停和撤销。机构管理大量用户、权益和服务目录的控制台仍属于机构侧独立表面，不塞进个人桌面客户端。

## 3A. 小步快跑开发约束

- 不做大规模架构调整，不迁移已成立的 Talk、Digital Self、Capability、Relay/A2A、Identity 或 Institution Distribution；
- 主要工作是现有功能优化、欠账落地、缺失入口补齐和成熟能力接入；
- 每个开发批次只交付一条普通用户可感知主链，原则上 1–2 周内可独立构建、回归和回退；
- 不以“统一改造”为理由批量重写 renderer、runtime、Store 或协议；只有现有结构确实阻断主链时才做最小局部调整；
- 每个小批次先通过开发者正式入口，再在阶段节点集中交 Owner 验收，不让 Owner 参与连续调试；
- 新字段、新 Store、新状态必须单独证明不可由现有事实派生，否则不增加。

## 5. Slice 1 — Discover 可用性恢复

### 用户主链

用户打开“发现” → 首屏看到当前且相关的内容 → 连续浏览至少 5 页不会长时间卡住 → 卡片整齐 → 打开原文或阅读正文 → 明确反馈影响下一轮。

### 实施边界

- 不增加搜索供应商，不做 PC 登录态平台抓取，不恢复观看入口专项；
- 重新核验 `publishedAt / fetchedAt / source freshness`，时间敏感内容和常青内容分开表达；
- 默认流优先当前内容，旧内容只有在明确相关且标明“背景/经典”时进入首屏；
- 本地队列耗尽前异步补量，网络/模型补量不得阻塞当前翻页；失败保留已可用页面并给出真实状态；
- 卡片标题、摘要、来源/时间和动作区采用一致布局；摘要截断、动作固定，适配 100%/125%/150% 缩放；
- 文字内容优先保证正文/原文可达、摘要可信、稍后看和带回 Talk 可用。

### 退出门

- 首屏时间敏感内容中至少 80% 为最近 7 天；超过 30 天的内容不得无标签混入“最新”；
- 真实来源连续 5 页/60 卡：重复 0，空页 0；已有缓存页响应 P95 ≤300ms，补量未就绪时 1 秒内出现可理解状态；
- 30 分钟真实使用中不出现超过 10 秒的无反馈中断；
- 60 个原文入口抽样可打开率 ≥95%，失效入口不继续推荐；
- 三种窗口宽度和三种缩放下没有重叠、动作错位或不可读卡片；
- 开发者正式 Electron 门通过后，才交 Owner 一次验收。

### Slice 1A 开发检查点（2026-11-24）

- 过期整屏缓存不再优先于更新目录；无更新内容时保留旧页并明确显示“较早内容”，不把旧页冒充最新；
- 后台候选在当前队列进入最后一页时提前接入，不再等完全归零后才开始衔接；
- 卡片改为同排等高、摘要限行、动作区贴底；超过 30 天且有可信发布时间的卡片显示“较早内容”；
- 构建及聚焦回归 39/39 通过，其中既有五页门为 5×12、60 张唯一卡；
- 正式 Electron/Playwright 门仍在启动阶段空转，未进入页面断言。本检查点不是 Slice 1 完成、真实来源门或 Owner 验收。

## 6. Slice 2 — Doing 领先能力集成

### 95% 的可执行定义

不以功能数量或宣传语计算“95%”。对每个支持的能力族建立真实任务集，以同一输入、授权和验收标准运行市场领先能力与 2digime；2digime 的加权完成分达到领先基准的 95% 才能称该能力族达到目标。未进入任务集的能力不得外推。

### 2A. 常用文档

- 集成成熟 DOCX、PPTX、PDF 生成与渲染能力，不靠模型直接拼二进制；
- Talk 中能创建、修改、继续迭代并打开 Word/PPT/PDF；
- 中文字体、分页、表格、图片、页眉页脚和导出 PDF 做结构与逐页视觉 QA；
- 至少覆盖报告、会议材料、演示文稿、表格型附件四类真实交付。

### 2B. 授权本地文件与工作区

- 用户选择文件夹后形成可撤销 Grant；允许列出、搜索、读取、创建、编辑、复制、移动、重命名和经确认删除授权范围内文件；
- 禁止越过授权根、跟随链接逃逸或读取浏览器/系统凭据；
- 文件改动保留差异、备份/回滚和真实回读；删除及不可逆覆盖继续需要确认；
- 本地文件管理作为 Capability 暴露给同一 Talk，不新增文件管理器事实源。

### 2C. Coding Agent

- 复用成熟 Codex/Claude Code 类 Agent，不自研 Coding Agent；首个正式适配以仓库已有 Codex 路线为主；
- 支持授权仓库检查、编辑、测试、构建、差异检查、提交建议和失败恢复；
- Agent 只得到任务级最小上下文，2digime 保留 Goal、Grant、Execution 和 Artifact 权威；
- 至少用 Web、桌面、后端和既有脏工作区四类项目做对照基准。

### 2D. 第三方系统

- 统一接入 MCP、OAuth/OIDC API、官方 Connector/Skill；不为每个网站写关键词路由或页面脚本；
- 完成“检查 → 草拟 → 高风险确认 → 执行 → 回执 → 失败恢复”合同；
- 首批选择三个零费用或已有授权的代表系统：日历/邮件、文档/存储、机构沙箱；
- 付费、发送、发布、删除、权限变更和敏感信息外发继续执行动作时确认。

### Slice 2 退出门

- DOCX/PPTX/PDF 各至少 10 个代表任务，结构/视觉/可打开综合通过率 ≥95%；
- 授权文件任务 20 项全部通过路径围栏和回读，越权负向门 100% 拒绝；
- Coding 任务集相对选定领先 Agent 的加权得分 ≥95%，并至少完成一个真实项目端到端修改；
- 三类第三方系统各完成一条真实低风险闭环和一条拒绝/撤销门；
- 所有结果回到同一 Talk，有真实文件、系统回执或可核验效果；说明文章不算执行完成。

## 7. Slice 3 — 数字之我右侧能力与关系投影

第一批只建立双栏骨架和“身份与授权”摘要；第二批再接协作关系；第三批在真实自动化成立后接自动化管理。任何一批都必须能独立验收和回退，不一次完成整页重构。

### 协作

- 展示已验证个人/机构 Subject Card、连接状态和允许范围；
- 可从“数字之我”右侧发起自然语言协作目标，随后进入同一 Talk；
- 展示收到/发出的请求、等待 Owner 决定、拒绝、失败、真实 Artifact 和撤销；
- 不把另一 Subject 变成 Tool/worker，不展示 A2A Task、exchange ID 等内部机制。

### 自动化

- 第一版只支持定时、文件到达、机构事件三类触发器；触发器不是语义路由器；
- 每条自动化必须绑定 Goal 模板、Capability/Subject 允许范围、有效期、费用上限和人在环节点；
- 运行仍进入既有 Execution/Artifact，失败回到 Talk；用户可暂停、恢复、撤销并查看最近结果；
- 完全自动执行只限明确授权的低风险动作；对外发送、付费、删除和权限变化仍要求动作时确认。

### 退出门

- 两个独立 Owner/Subject 完成接受、拒绝和结果交付；
- 一条人在环自动化和一条低风险全自动化连续运行 10 次，无越权、重复执行或假完成；
- 隐藏右侧投影后，Talk、Digital Self、Goal、Grant、Execution、Artifact 和协作事实仍完整成立；
- Owner 能在不理解协议术语的情况下发起、停止和撤销。

## 8. Slice 4 — 机构伙伴就绪

### 个人客户端投影

- 显示已连接机构、验证级别、权益、可用服务、授权范围、有效期和撤销；
- 明示机构能看到的最小计量，以及不能读取的 Digital Self、私人 Talk、文件和记忆；
- 机构服务以已验证 Subject/Capability 进入 Talk 与协作，不建立机构专用聊天内核。

### 机构伙伴沙箱

- 复用已接受 Institution Distribution：Organization、用户映射、权益、用量归集和 Brand Kit；
- 增加可演示控制台：测试用户、权益、服务 Subject、A2A endpoint、授权策略、最小审计和停用；
- 提供 OpenAPI/事件合同、OIDC/FAPI 2.0 目标配置、A2A/Agent Card、白标包和隐私数据流说明；
- 用合成数据演示“电信权益发放”和“银行服务协作”两条旅程，不冒充真实运营商/银行接入。

### 退出门

- 伙伴在 60 分钟内可按文档启动沙箱、创建机构、两个测试用户和一项服务；
- 用户完成机构登录、权益到账、一次 Talk 能力调用、一次机构 Subject 协作和撤销；
- 机构侧只有必要身份映射、权益和用量，没有 prompt/response、Digital Self、私人文件或长期记忆；
- 输出可供合作沟通的架构图、接口清单、安全边界、试点范围与验收清单。

## 10. 风险、依赖与停止条件

| 风险 | 处理 |
|---|---|
| Discover 再次陷入补丁循环 | 不增站点/关键词特例；数据新鲜度、队列和 UI 分层验证；同问题第二轮无改善即重审对象边界 |
| 数字之我右侧变成第二套 workflow | 右侧只投影既有事实；启动后回 Talk；隐藏右侧后底层仍成立 |
| 95% 目标无限扩张 | 按能力族和固定真实任务集计分；一个能力族过门后停止自研 |
| 外部 Agent/Connector 供应商锁定 | 统一能力合同、可替换适配器、结果回读；不把品牌写入语义路由 |
| 机构需求拖成大型 SaaS | 先沙箱和两条伙伴旅程；没有真实伙伴前不做多租户运营平台 |
| 安全边界阻碍可用性 | 扩大“授权后能做”的范围，而不是永久禁止；高风险动作仍在执行时确认 |

# DISCOVER-WATCH-ENTRY-01 — 从推荐对象到可消费入口

**日期：** 2026-11-22  
**状态：** `OWNER_ACCEPTED_LIMITED / PUBLIC_ECOSYSTEM_BOUNDARY_ACCEPTED / CLOSED / NOT_RELEASED`  
**前序：** `DISCOVER-50-STAGE1` 已获 Owner 限定接受  
**目标：** 用户表达“想看”时，推荐卡优先交付可核实的直接观看、试看/预告或官方平台作品入口；新闻、榜单、百科和评论退回推荐依据。

## 1. 用户主链

```text
用户用自然语言说想看什么
  → 当前模型结合 Digital Self 选择具体作品
  → 当前模型自主搜索作品及其消费入口
  → 通用页面读取 / 媒体元数据返回真实访问事实
  → 当前模型整体选择作品与最佳入口
  → 卡片显示：直接观看 / 试看或预告 / 打开平台 / 暂无已核实入口
  → 报道、榜单、百科只在“推荐依据”中出现
```

验收终点不是“搜到与作品相关的文章”，而是用户能从具体作品卡继续消费；若平台限制阻断，则系统明确说明限制和仍可用的最近入口。

## 2. 问题判断

当前主链已经具备：

- 同一当前模型的 `web_search` + `present_results` 工具环；
- Digital Self、本次请求、明确控制和短期上下文的一次整体选择；
- 候选 ID 与依据 URL 分离；
- 安全页面读取、公开网页正文读取、开放媒体元数据/oEmbed、观看入口/发现依据字段等既有能力。

当前缺口不是再造推荐算法，而是非 Responses 主链只把搜索摘要交给模型，没有把现有的页面读取和媒体入口事实作为通用工具交给同一模型。于是模型可以推荐作品，却常常只能用报道候选作依据，无法核实最后一跳。

## 3. Build-vs-Integrate Gate

### 推荐路线：复用现有通用能力

1. 继续让当前模型决定搜什么、读哪个候选、是否补搜具体作品与入口。
2. 把已有安全页面读取/正文读取/公开媒体元数据能力接入同一工具环；不新建平台关键词路由、站点白名单或观看评分器。
3. Search 仍只接收必要查询，不接收完整 Digital Self；页面读取只返回候选页面的实际内容、最终 URL、媒体元数据和访问失败事实。
4. runtime 只校验候选 ID、URL、安全、重定向、读取成功/失败和超时，不判断“这部剧值不值得推荐”。

这是默认路线：改动较小，复用现有能力，并保持模型中立和平台中立。

### 备选路线：官方平台连接器或授权登录态 Computer Use

仅当公开搜索 + 通用页面读取在代表性样本上仍无法达到覆盖门槛时，再逐个平台评估：

- 官方公开 API、oEmbed、开放作品页或可嵌入预览；
- 经 Owner 明确授权的登录态浏览器/Computer Use，只完成打开和访问，不保存密码、不绕过验证码、付费、地区或平台安全限制。

该路线覆盖更高，但涉及账号授权、平台条款、隐私和维护成本，不作为第一刀。

### 停止条件

若方案开始依赖短剧关键词、站点域名表、平台专用抓取器、解析私有接口、绕过登录/付费/地区限制，立即停止并重读 00/01/02。若公开能力达不到门槛，应诚实进入平台连接器决策，不用更多规则伪装完成。

## 4. 最小实现顺序

### Slice 0 — 能力审计与真实基线

- 选取至少 12 个具名作品请求和 8 个开放推荐请求，覆盖短剧、长视频、纪录片或公开节目等不同消费对象。
- 记录当前每个主卡属于：具体作品、报道/榜单、百科、观看页、试看/预告、平台作品页，以及实际打开结果。
- 先证明现有 `web_search`、安全页面读取、媒体元数据各能提供什么；未完成审计前不写新平台代码。

### Slice 1 — 同一模型核实候选

- 在 `runChatContentSeek` 的同一工具环中复用通用候选读取能力；模型通过 candidate ID 选择要核实的页面，不能读取任意内网或越过现有 SSRF 门。
- 工具返回实际最终 URL、页面标题/摘要、可识别媒体或 oEmbed、读取状态和限制事实；不输出“相关性分数”。
- 保持 30 秒第一终态：优先交付少量高质量具体作品与入口，不用更多低质量卡换数量。

### Slice 2 — 作品与入口交付

- `main` 只交付具体消费对象；报道、榜单、百科和评论只能作为 `basisSource` 或 related。
- 复用现有 `channelUse`、`entrancePurpose`、`access`、`basisSource` 等字段，避免新增第二套观看状态。
- 主动作按真实事实投影：
  - 已核实可播放或可公开预览 → “直接观看”或“试看/预告”；
  - 已核实官方平台作品页但需登录/付费/App → “打开平台”，并显示限制；
  - 只有推荐依据 → 具体作品卡显示“暂未核实到观看入口”，依据按钮降为次动作。
- 显式“想看”请求的结果区不得用默认个人流新闻补位。

### Slice 3 — 失败与授权边界

- 登录、付费、地区、下架、App 跳转、验证码、读取失败分别如实展示，不合并为“可直接观看”。
- 不自动登录、不保存密码、不购买、不绕过平台限制。
- 平台入口失效不删除已确认的作品对象；下一次可重新搜索入口，但不得把旧失败页冒充可用。

## 5. 验收门

### 开发者门

1. 20 个代表性请求中，显式消费请求的主卡 100% 为具体内容对象，报道/榜单/百科占主卡为 0。
2. 至少 70% 的主推荐对象具有已实际打开核实的直接观看、试看/预告或官方平台作品入口；其余对象必须明确标“暂未核实到观看入口”。
3. 具名对象请求至少交付 1 个可消费入口，或给出可核实的不可用/受限事实；不得只返回新闻报道。
4. 抽样入口标题/页面对象匹配率 100%，404、错误对象、首页/搜索页冒充具体入口为 0。
5. 首批有用结果仍在 30 秒内形成终态；若入口核实尚未完成，先诚实交付具体作品与状态，不静默等待。
6. Search、页面读取和模型失败不污染代次；A→B→C 只保留 C。现有相关专项回归、构建和正式 Electron 门通过。

### Owner 门

开发者门通过后只安排一次最小体验：

- 一个具名作品；
- 一个开放“最近想看什么”的推荐；
- 一个明确要求试看/预告的请求。

Owner 只判断：卡片是否真能把人带到消费入口、限制是否说清、报道是否退到次要位置。不得要求 Owner 收集日志或重复调试。

## 6. 本阶段不做

- 不自研搜索引擎、整站爬虫、播放器或盗版聚合。
- 不做短剧关键词特例、站点黑白名单、相关性分数或第二套推荐器。
- 不绕过登录、付费、验证码、地区限制、DRM 或平台 App 约束。
- 不承诺所有作品免费或无需账号；目标是入口真实、限制透明、报道不冒充入口。
- 不 push、合并、发布或启用付费能力，除非 Owner 后续单独授权。

## 7. 2026-11-22 实施检查点

本轮已完成最小实现，但开发者门未通过，不能进入 Owner 复验：

- 同一模型工具环已接入受候选 ID 约束的 `read_candidate`；真实页面读取后，模型可交付完整观看、试看/预告、平台页和访问限制。
- 未读取页面不得标成完整观看、试看或平台页；推荐对象与报道依据已分离，报道/榜单/百科不再进入主卡。
- 同一轮独立页面读取并行执行；按钮区分“去原站观看 / 打开试看或预告 / 打开平台页 / 查看依据”。
- TypeScript 构建通过；相关 4 个测试文件 13 项通过。
- 真实 12 个具名请求检查点：21 张具体对象主卡中 18 张带已读取入口，入口覆盖率 86%；9/12 在 30 秒内，1 个具名短剧请求空结果。
- 真实 8 个开放推荐 v4：23 张具体对象主卡中 12 张带已读取入口，入口覆盖率 52.2%；2/8 在 30 秒内。主卡报道/榜单/百科为 0。

因此当前公开能力只证明“已知作品找入口”大幅改善；“先选作品，再为作品找入口”的开放推荐和 30 秒终态仍未成立。连续三轮同层调整未过门，按 02 的 Red 规则停止继续补提示词或站点特例。

下一步需要能力路线决策：

1. **推荐：增强 Relay 的成熟搜索供应商与容量。** 复用现有 provider-agnostic failover，接入对中文影视和平台作品页更可靠的成熟搜索提供方；需要新的服务器端凭证、可能产生费用，并需单独部署授权。
2. **备选：Owner 明确授权登录态 Computer Use。** 仅在已登录平台内搜索和打开作品/试看页；不保存密码、不自动登录、不购买、不绕过验证码、付费、地区或 DRM。该路线需要逐平台账号授权和条款评估。

官方开放平台审计未发现可无授权覆盖通用影视目录的接口：抖音关键词视频搜索需要特殊权限与用户 OAuth，且只返回最近 1 天；B 站开放平台公开说明主要覆盖授权账号稿件管理；腾讯视频、优酷未核实到可直接用于通用作品搜索的公开官方目录 API。不得因此转向非官方私有接口或平台爬虫。

完整证据见 `docs/audits/DISCOVER-WATCH-ENTRY-01-SESSION-01.md`。

## 8. 2026-11-22 零费用能力路线检查点

Owner 已授权继续推荐路线，但明确不授权任何外部费用。能力审计因此只允许使用已有免费额度或“额度耗尽即停”的免费计划，不允许绑定付费方式、购买资源、开启超额计费或把试用额度包装成生产容量。

现场结论：

1. 北京 Relay 当前只配置了 IQS；没有 Gemini 或其他第二搜索凭据。服务健康，仍以未显式配置时的 `CNAuto` 为主引擎。
2. 在原有“免费额度耗尽后停止”边界下，对 `CNAuto` 与 `CNLiteBasic` 各做 4 次开放影视检索。两者均成功返回，但 `CNLiteBasic` 没有形成可用补强；`CNAuto` 也只有部分样本出现爱奇艺或优酷入口，其余仍以盘点、聚合或新闻为主。不得把双引擎回退记为质量修复。
3. Gemini 3+ 的 Google Search Grounding 不在 API 免费层中；启用需要付费层，虽有月度免费搜索量，但超额后会计费，不符合本轮授权。
4. Google Custom Search JSON API 已停止接纳新客户；Brave Search API 需要信用卡和计划激活，均不采用。
5. Tavily Researcher 官方计划提供每月 1,000 免费 credits、无需信用卡，额度耗尽后请求停止；基础 Search 每次 1 credit。它是当前推荐的零费用成熟能力候选。

下一最小动作：经 Owner 明确授权后创建一个免费 Tavily 账户和 API key，只选择 Researcher 免费计划，不录入付款方式、不启用 Pay As You Go；凭据只进入 Relay 服务端 Secret。先用既有 12+8 样本执行独立能力 benchmark，通过后才写最小 provider adapter、部署 Relay 并重跑开发者门。若 Tavily 不能达到门槛，停止本路线，不继续叠加供应商或提示词补丁。

能力审计证据见 `docs/audits/DISCOVER-WATCH-ENTRY-01-CAPABILITY-SESSION-02.md`。

## 9. 2026-11-22 Tavily 独立能力验证

Owner 已授权创建免费凭据并执行零费用能力验证。现场只使用既有 Researcher 免费计划；未录入付款方式，Pay As You Go 保持关闭。首次生成的专用 key 因在创建成功界面被自动化可访问树回显，已立即撤销；替代 key 未写入 Git、日志或证据，基准期间只通过受控临时文件传递，读取后立即删除。

验证结果：

1. Basic 对完整 12 个具名 + 8 个开放样本执行 20 次请求，消耗 20 个免费 plan credits；20/20 均在 10 秒内完成，但自动初筛仅 5/20 出现疑似入口，具名与开放覆盖均为 25%。
2. 对现有能力缺口中的 8 个样本再执行 Advanced，消耗 16 个免费 plan credits；自动初筛为 3/8，但人工复核后均不是可靠净增：包括泛频道、盘点文章、同名 AI 二创或与既有 IQS 结果重复的正式片源。
3. 唯一较明确的正式片源是《哪吒之魔童闹海》平台页，现有主链已经有多条已读取入口；其余疑似命中不能满足“具体作品 + 实际消费入口”的门槛。
4. 因此 Tavily 在当前零费用层没有证明能补足开放推荐或缺失具名作品入口。速度通过不等于质量通过，不写 provider adapter、不把泛频道冒充作品入口、不部署 Relay。

本路线按 02 Red 与本计划停止条件结束：不继续叠加免费供应商、站点域名表、查询改写或提示词补丁。后续只有在 Owner 对下列产品路线作出新选择后才能继续：接受当前公开能力边界；授权逐平台登录态 Computer Use/官方连接器评估；或另行授权具有费用与容量保障的成熟搜索能力。完整证据见 `docs/audits/DISCOVER-WATCH-ENTRY-01-CAPABILITY-SESSION-03.md`。

## 根因与修复

1. 托管模型请求在收到 headers 后释放超时与取消监听，响应体读取不再受约束。现在覆盖到正文解析结束，并区分 HTTP 错误、网络失败、空正文、格式错误、截断及主动取消。空截断保留 finish_reason=length、HTTP 与长度，不能当作有效结构化结果。
2. JSON 错误原先被吞为默认对象；空截断转成通用错误丢失原因。现在仅记录 json/envelope/schema 错误类别，不记录响应、提示词、材料正文、provider 原始错误或密钥。阶段日志存入现有包的 content/discovery-diagnostics.ndjson，包含 generation/request 标识、阶段、HTTP、finishReason、outputLength、parseError、cancellation、failure。HTTP 未知为 null，不能推定 200；搜索输出长度为返回对象数，模型输出长度为字符数。
3. 分阶段 45/90 秒重试可能越过 Discover 的 60 秒总窗口。现在全流程持有同一 deadlineAt，模型与公开页读取只使用剩余时间；读取正文、重定向及结构化下一次尝试均检查取消/截止。用户取消、替代请求、deadline、其他 caller 取消分开记录。未加长超时、未增加重试或放宽匹配。
4. 失败视图原先清空候选，搜索摘要仅停留在预览。现在搜索得到的摘要立即写入现有内容存储，待判断仍明确标识；同一请求失败保留既有结果，replenishing=false。旧查询结果不混入新目标。对话本人信息学习未整体停用，没有新增画像或总控存储。

## 服务端待办（未修改、未部署）

源码 ai-inference-gateway.ts 的 provider 重试每次继续使用固定 timeoutMs；客户端 deadline 未构成服务端 provider 共用截止合同。客户端及时结束不能证明供应商已停止计费或服务端停止工作。需另项修复并验证 HTTP 断开到 provider AbortSignal、重试共用剩余时间，以及服务端阶段、requestId、finish_reason 和输出长度诊断。当前客户端已发送 thinking，但网关 provider 参数仍未转发；本轮不据此宣称空输出供应商问题已修复。历史 AVAILABLE + outputTokens=0 无法独自确定截断/空正文/解析/取消根因。
